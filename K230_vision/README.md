# K230 视觉代码

本目录用于存放 K230/CanMV 视觉端代码，与 MSPM0G3507 的行驶控制代码分开维护。

## 目录约定

- `src/`：本项目实际部署到 K230 的 CanMV MicroPython 代码。
- `models/`：本项目使用的 `.kmodel` 及其标签、输入尺寸和量化信息。
- `protocol/`：K230 与 MSPM0 之间的通信协议说明和测试数据。
- `vendor_reference/`：从开发板出厂 SD 卡中筛选出的厂家示例，仅用于参考，不直接作为比赛入口。

## 当前情况

2026-07-24 已将出厂 SD 卡完整复制到本地参考目录。备份包含 273 个文件、约 326 MB，确认其中具有二维码、人脸检测、人脸注册、人脸识别、圆形检测等示例，以及对应 K230 模型。

2026-07-25 已在 `src/main.py` 完成第一版钢珠识别程序：

- 使用固件内置 `cv_lite` 霍夫圆检测，不需要额外模型。
- 使用低饱和度、高光和阴影特征过滤非金属圆形。
- 连续多帧稳定确认后输出中心坐标、像素半径和质量分数。
- 通过 K230 UART1 以 115200 bit/s 输出结果。

完整出厂备份体积较大且配置中可能含厂商凭据，已通过 `.gitignore` 排除，不应原样提交。

## 开发原则

1. 先保留并备份出厂 SD 卡内容，不直接在唯一副本上修改。
2. 厂家示例只用于确认摄像头、显示和模型调用方式。
3. 比赛入口统一放在 `src/main.py`，不依赖厂家菜单界面。
4. K230 只输出结构化识别结果；MSPM0 负责路线状态机、电机、电磁铁和故障保护。
5. UART0 已由八路循迹模块占用，K230 与 MSPM0 必须使用另一组 UART 或其他独立接口。

## 下一步

1. 在 CanMV IDE 中手动运行 `src/main.py`，先确认画面和圆形候选框正常。
2. 用实际钢珠和比赛背景标定像素半径、检测区域及金属外观阈值。
3. 记录稳定帧率、最远识别距离、漏检和误检样本。
4. 为 MSPM0 配置一组不与八路循迹 UART0 冲突的接口，并实现 `BALL` 帧解析。
5. 只有在主控状态、目标位置和超时条件全部满足时，才允许主控驱动电磁铁。
